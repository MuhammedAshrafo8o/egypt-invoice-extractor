# دفتر — مساعد المحاسب لفواتير عملائه

منصة للمحاسب بتستلم فواتير عملائه (رفع ملفات، أو من الواتساب، أو سحب مباشر من منظومة الفاتورة الإلكترونية)، وبتقراها وتراجعها أوتوماتيك، وبتجهز ملخص إقرار ضريبة القيمة المضافة لكل عميل كل شهر، مع تصدير Excel.

> النسخة دي **نسخة تجريبية (MVP)** معمولة عشان تتجرب مع أول محاسبين.

---

## التشغيل في ٣ خطوات

**المطلوب:** Python 3.10 أو أحدث ([تنزيل](https://www.python.org/downloads/)). على ويندوز علّم على **Add Python to PATH** وإنت بتسطّب.

```bash
git clone https://github.com/MuhammedAshrafo8o/egypt-invoice-extractor.git
cd egypt-invoice-extractor
```

**1. التسطيب (مرة واحدة)**

| النظام | الأمر |
|---|---|
| ويندوز (PowerShell) | `.\setup.ps1` |
| ماك / لينكس | `./setup.sh` |

السكريبت بيعمل الآتي:
- يعمل بيئة Python منفصلة.
- يسطّب كل المكتبات.
- يعمل ملف `.env`.
- يجهز حساب تجريبي فيه فواتير.
- يشغّل الاختبارات.

> لو PowerShell رفض يشغّل السكريبت: `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` وبعدين جرّب تاني.

**2. التشغيل**

```bash
# ويندوز
.venv\Scripts\python -m app
# ماك / لينكس
source .venv/bin/activate && python -m app
```

**3. افتح** http://localhost:8000 وادخل بالحساب التجريبي:
- الإيميل: `demo@example.com`
- كلمة السر: `demo1234`

### أو بـ Docker
```bash
cp .env.example .env
docker compose up --build
docker compose exec app python -m app demo   # بيانات تجريبية (اختياري)
```

## المنصة بتعمل إيه

### للمحاسب (لوحة التحكم)
- **حسابات منفصلة لكل محاسب:** كل محاسب بيشوف عملاؤه بس.
- **العملاء:** اسم العميل، ورقمه الضريبي، ورقم الواتساب بتاعه، وبيانات ربطه بالمنظومة.
- **رفع الفواتير:** بالسحب والإفلات، لحد ٥٠ ملف في المرة (`MAX_FILES_PER_UPLOAD`)، وكل ملف بيتسجل فاتورة لوحده. الملف الواحد بيتقري على طول ويفتح، والأكتر بيتقروا في الخلفية (`UPLOAD_WORKERS` في نفس الوقت) مع شريط تقدّم، وتقدر تكمّل شغلك أو تقفل الصفحة.
- **PDF فيه كذا فاتورة:** علّم «كل صفحة في الـ PDF فاتورة لوحدها» قبل الرفع، وكل صفحة بتتسجل فاتورة. ولو نسيت، السيستم بينبّهك إن الملف فيه كذا صفحة.
- **الملخص بيفصل اللي لسه ماتراجعش:** تحت ضريبة المخرجات والمدخلات بيقول قد إيه منها جاي من فواتير لسه ماتراجعتش، والصافي بيتكتب «مبدئي» لحد ما تخلص.
- **مفيش فاتورة بتترفع مرتين:** نفس الملف بالظبط (حتى باسم تاني) بيتخطّى. ونفس الفاتورة بصورة تانية بتتعلّم كمتكررة (نفس المورد ورقم الفاتورة)، أو كمتكررة محتملة (نفس المورد ونفس اليوم ونفس الإجمالي) لو الرقم مش واضح.
- **شاشة المراجعة:**
  - الفاتورة الأصلية جنب البيانات المستخرجة.
  - الأخطاء والملاحظات مكتوبة بالعربي.
  - التعديل بيتحقق منه وإنت بتكتب (النسبة والإجمالي).
  - زرار "اعتماد واللي بعدها" عشان تراجع بسرعة.
- **التفرقة بين المبيعات والمشتريات أوتوماتيك:** لو العميل هو البائع تبقى مبيعات، غير كده مشتريات.
- **ملخص الشهر لكل عميل:** ضريبة المخرجات، وضريبة المدخلات، وصافي الضريبة (مستحق أو رصيد دائن).
- **تصدير Excel بالعربي (٤ شيتات):** ملخص الإقرار، والمشتريات، والمبيعات، والمشتريات حسب المورد. المعادلات حقيقية (`SUMIFS`)، والتواريخ تواريخ فعلًا، وفيه فلتر على كل عمود. كل فاتورة قدامها عمود "محتسبة في الإقرار"، فالفواتير اللي بعملة أجنبية أو اللي فيها أخطاء ومش معتمدة بتظهر بس مش بتدخل في الحساب، وأرقام الملف بتطابق أرقام المنصة.

### البحث والتحليلات
- **صفحة الفواتير:** بحث في كل فواتير كل العملاء باسم المورد، أو رقم الفاتورة، أو الرقم الضريبي، أو المبلغ. البحث مش بيفرق بين الأ والا والإ، ولا بين الأرقام العربية والإنجليزية، ولا بالشرط أو الفاصلة. وفيه فلاتر (العميل، والشهر، والحالة، والنوع، والمصدر، والتاريخ، والمبلغ)، وترتيب، وتصدير النتايج CSV.
- **البحث السريع (`Ctrl + K` أو `/`):** من أي صفحة، اكتب اسم عميل أو مورد أو رقم فاتورة وافتحه بـ Enter.
- **التحليلات:** صافي الضريبة لكل العملاء مقارنةً بالشهر اللي فات، ورسم لضريبة المخرجات والمدخلات آخر ٦ شهور، والفواتير جت منين (رفع، واتساب، منظومة)، والعملاء اللي صافي ضريبتهم اتغيّر جامد (عشان تراجعه قبل الإقرار)، وأكبر الموردين، وأكتر المشاكل في الفواتير.

### طريقة الشغل اليومية
- **الرئيسية:** بتبيّن "عندك كام فاتورة محتاجة مراجعة"، وميعاد الإقرار الجاي (بيتظبط من `VAT_DEADLINE_DAY`)، وكل عميل قدامه شريط تقدّم لحد ما يوصل لختم **"جاهز للإقرار"**.
- **محتاج مراجعة:** قايمة واحدة بكل الفواتير اللي محتاجة شغل عند كل العملاء، الأخطاء الأول.
- **وضع المراجعة:** "ابدأ المراجعة" بيفتح الفواتير ورا بعض. صلّح اللي متعلّم بالأحمر، و `Ctrl + Enter` تعتمد وتروح للي بعدها. وفيه تكبير ولف للصورة.
- **رفع الفواتير:** بمجرد ما تختار الملفات أو تسحبها، بتترفع وتتقري.
- **متابعة العملاء على الواتساب:** "اطلب الفواتير" بيفتح واتساب المحاسب برسالة جاهزة للعميل (من غير أي إعداد)، والصفحة الرئيسية بتبيّن العملاء اللي لسه مابعتوش. ومن أي فاتورة فيها مشكلة: "اسأل العميل على واتساب" والرسالة فيها المشكلة نفسها.
- **ذاكرة الموردين:** بعد ما المحاسب يعتمد مورد، اسمه بيتملى لوحده بعد كده، وأي رقم ضريبي **بيفرق رقم واحد** عن مورد معروف بيتعلّم (أشهر غلطة قراءة).
- **تقرير شهري للعميل:** صفحة باسم المكتب فيها الضريبة المستحقة والفواتير الناقصة، تتطبع أو تتحفظ PDF وتتبعت لصاحب الشركة.
- **اعتماد مجمّع:** اختار الفواتير اللي محتاجة نظرة بس واعتمدها مرة واحدة (الفواتير اللي فيها أخطاء لازم تتصلح واحدة واحدة).
- **الوقت اللي اتوفر:** الصفحة الرئيسية بتقول تقريبًا الوقت اللي السيستم وفّره الشهر ده.
- الخط: [Alexandria](https://fonts.google.com/specimen/Alexandria) (رخصة OFL)، ومتضمّن في المشروع فبيشتغل من غير إنترنت.

### القراءة والتحقق
| نوع الملف | الطريقة |
|---|---|
| فاتورة إلكترونية عليها QR | قراءة الـ QR، ولو العميل مربوط بالمنظومة بتتسحب بياناتها الرسمية |
| PDF رقمي (عربي أو إنجليزي) | قراءة النص + إصلاح النص العربي اللي بيطلع معكوس من بعض البرامج |
| صورة أو PDF ممسوح | ذكاء اصطناعي (Claude أو Gemini أو غيرهم) لو متظبط، وإلا **OCR مجاني** (Tesseract) من غير إنترنت |

**طبقة التحقق:**
- الرقم الضريبي لازم يكون ٩ أرقام.
- الإجمالي = المبلغ + الضريبة.
- نسبة الضريبة منطقية.
- التاريخ مش في المستقبل ومش قديم أوي.
- **الفاتورة مش متكررة** في نفس الدفعة أو في كل الفواتير اللي اتسجلت قبل كده.

### الواتساب
العميل يبعت صورة الفاتورة على رقم الواتساب بتاع المكتب، فتدخل نفس طابور القراية (فلو بعت ٤٠ صورة مرة واحدة مش بيضغط على الذكاء الاصطناعي)، وتتسجل له أوتوماتيك، ولو بعت نفس الصورة مرتين التانية بتتخطّى، ويوصله رد فيه اللي اتقرا (المورد والإجمالي وحالة الفاتورة). ولو الرقم مش مسجل لأي عميل، بيوصله رد إنه يكلم المحاسب.

### منظومة الفاتورة الإلكترونية
بعد ربط بيانات العميل، فيه زرار **سحب من المنظومة** بيجيب كل فواتير الشهر الإلكترونية (مبيعات ومشتريات) معتمدة على طول، من غير ما حد يرفع أي ورق.

**مطابقة المشتريات:** وإنت بتسحب، أي فاتورة اترفعت (صورة أو PDF) ولها نسخة إلكترونية بتتربط بيها: بياناتها بتتاخد من المنظومة وبتتعتمد، ومن غير ما تتكرر. وفواتير المشتريات اللي **مش موجودة على المنظومة** بتتعلّم، وصفحة العميل بتقول ضريبتها كام (لأن الخصم بيتم بالفواتير الإلكترونية بس)، وفيه رسالة واتساب جاهزة للعميل بالقايمة عشان يطلبها من الموردين.

**إصدار فواتير المبيعات:** زرار **فاتورة مبيعات إلكترونية** في صفحة العميل، أو **إصدار فاتورة إلكترونية** من أي فاتورة مبيعات اترفعت ورق (بياناتها بتتملى لوحدها):
- **من صورة:** ارفع صورة الفاتورة الورق (مطبوعة أو بخط اليد) في صفحة الإصدار، والمشتري والأصناف والكميات والأسعار بيتملوا لوحدهم بالذكاء الاصطناعي، وإنت بتراجع بس. من غير ذكاء اصطناعي، بيتملى المشتري والإجماليات في سطر واحد.
- المشتري: شركة، أو شخص، أو جهة أجنبية. عنوان الشركات بيتحفظ ويتملى لوحده المرة الجاية.
- الأصناف: الكمية والسعر والخصم والضريبة (١٤٪، أو نسبة تانية، أو معفاة، أو تصدير)، والإجماليات بتتحسب وإنت بتكتب.
- قبل الإرسال، السيستم بيقولك بالعربي إيه الناقص (كود النشاط، العنوان، كود الصنف، الرقم الضريبي…).
- **وقّع وابعت للمنظومة:** بيوقّع بالتوكن (أو ملف شهادة PFX)، ويبعت، ويعرض حالتها (مقبولة، أو مرفوضة والأسباب)، ولينك الفاتورة على البوابة.
- الفاتورة اللي اتقبلت بتتقفل ومينفعش تتعدل، وبتدخل في ضريبة المخرجات.

## تفعيل المزايا (ملف `.env`)

### قراءة الصور والـ PDF الممسوح

البرنامج بيختار أوتوماتيك حسب اللي متظبط، والطريقة المستخدمة ظاهرة فوق في الشاشة:

| الطريقة | التكلفة | الدقة | الإعداد |
|---|---|---|---|
| **OCR مجاني (Tesseract)** | مجاني، ومن غير إنترنت | كويسة مع الفواتير المطبوعة الواضحة، وضعيفة مع خط اليد | سكريبت التسطيب بيعمله، أو `python -m app setup-ocr` |
| **Gemini** | فيه خطة مجانية بحد يومي | عالية | `GEMINI_API_KEY` من [AI Studio](https://aistudio.google.com/apikey) |
| **Ollama على جهازك** | مجاني بالكامل | متوسطة إلى عالية، ومحتاجة جهاز قوي | `OPENAI_BASE_URL=http://localhost:11434/v1` و `OPENAI_MODEL=qwen2.5vl` |
| **OpenRouter / Groq** | فيه موديلات مجانية بحدود | متفاوتة | `OPENAI_BASE_URL` و `OPENAI_API_KEY` و `OPENAI_MODEL` |
| **Claude** | مدفوع (قروش للفاتورة) | الأعلى | `ANTHROPIC_API_KEY` |

- **لو الذكاء الاصطناعي فشل** (مثلًا الحد المجاني خلص)، البرنامج بيرجع للـ OCR المجاني أوتوماتيك.
- **الفواتير اللي اتقرت بالـ OCR** بتتعلّم "مراجعة" دايمًا، عشان المحاسب يبص على الأرقام، وخصوصًا الرقم الضريبي.

> ⚠️ **الخطط المجانية (زي Gemini):** جوجل بتقول إن بيانات الخطة المجانية ممكن تتستخدم لتحسين خدماتها. استخدمها للتجربة بفواتير تجريبية، مش بفواتير عملاء حقيقيين.

**تسطيب Tesseract يدوي** (لو سكريبت التسطيب ماعرفش):

| النظام | الأمر |
|---|---|
| ويندوز | `winget install UB-Mannheim.TesseractOCR` |
| ماك | `brew install tesseract` |
| لينكس | `sudo apt install tesseract-ocr` |

وبعدين في كل الحالات: `python -m app setup-ocr` (بينزّل اللغة العربية).

### الواتساب (WhatsApp Cloud API)
1. اعمل تطبيق على [developers.facebook.com](https://developers.facebook.com) من نوع **Business** وضيف له **WhatsApp**.
2. من **API Setup** خد **Phone number ID** و **Access token**. يُفضّل System User token دائم بدل المؤقت.
3. من **Settings → Basic** خد **App Secret**.
4. اكتبهم في `.env`، واختار أي كلمة لـ `WHATSAPP_VERIFY_TOKEN`.
5. البرنامج لازم يكون له رابط HTTPS عام:
   - للتجربة: [ngrok](https://ngrok.com) أو [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) (`ngrok http 8000`).
   - للتشغيل: سيرفر عليه دومين.
6. في **WhatsApp → Configuration → Webhook**:
   - **Callback URL:** `https://رابطك/webhooks/whatsapp`
   - **Verify token:** نفس الكلمة اللي اخترتها.
   - اشترك في **messages**.
7. في صفحة كل عميل، اكتب رقم الواتساب بتاعه (مثلًا `01001234567`).

> في وضع التجربة عند Meta، لازم تضيف أرقام المستلمين في قايمة الأرقام المسموحة.

### منظومة الفاتورة الإلكترونية
1. العميل (أو المحاسب بتوكيله) يدخل [بوابة المنظومة](https://invoicing.eta.gov.eg).
2. يسجّل **ERP System**، وياخد **Client ID** و **Client Secret**.
3. اكتبهم في صفحة العميل ← **بيانات العميل والربط**.
4. ابدأ بـ `ETA_ENV=preprod` (بيئة التجربة)، وبعدين `prod`.

**عشان تصدر فواتير مبيعات** (مرة واحدة لكل عميل، من صفحة العميل ← **إعدادات إصدار الفاتورة الإلكترونية**):
- كود النشاط، والعنوان المسجّل، وكود الفرع (٠ للرئيسي).
- كود صنف مسجّل على المنظومة (EGS أو GS1). العميل لازم يكون مسجّل أكواد أصنافه على البوابة.
- التوقيع: التوكن متوصل بالجهاز اللي شغّال عليه البرنامج، و`pip install PyKCS11`، ومكان مكتبة التوكن في `ETA_PKCS11_LIB`. أو ملف شهادة PFX. الرقم السري بيتكتب وقت الإرسال ومش بيتحفظ.

**عايز تجرب من غير بيانات دخول؟** شغّل بـ `ETA_ENV=demo`: محاكي داخل البرنامج بيوقّع بشهادة تجربة ويراجع الإجماليات والتوقيع زي المنظومة، ومش بيبعت أي حاجة للمصلحة. وأمر `python -m app demo` بيجهّز عميلين بإعداداتهم.

> ⚠️ الربط مع المنظومة متبني حسب توثيق الـ SDK الرسمي، والتوقيع (CAdES-BES) متراجع بـ OpenSSL، والدورة كلها متجربة على المحاكي، لكن **لسه ماتجربش ببيانات دخول حقيقية ولا بتوكن حقيقي**. أول تجربة لازم تكون على بيئة preprod.

## الاختبارات

```bash
python -m unittest discover tests
```

٧٦ اختبار، وبيغطوا:
- الاستخراج من PDF عربي وإنجليزي، ومن النص المعكوس.
- قواعد التحقق، وكشف التكرار.
- تسجيل الدخول والصلاحيات (محاسب ما يشوفش عملاء محاسب تاني)، والحماية من CSRF.
- رفع الفواتير ومراجعتها وتعديلها واعتمادها ومسحها.
- ملف الـ Excel.
- الواتساب بشكل كامل، بما فيه التحقق من التوقيع وتجاهل الرسائل المكررة.
- شكل الطلب اللي بيتبعت لكل مزوّد ذكاء اصطناعي (Claude و Gemini والمتوافق مع OpenAI)، وإعادة المحاولة لو الخدمة عليها ضغط، والتحويل لموديل بديل.
- القراءة المجانية (OCR) على صور حقيقية بالعربي والإنجليزي، والرجوع ليها لو الذكاء الاصطناعي فشل.
- السحب من المنظومة، ومطابقة المشتريات المرفوعة مع نسختها الإلكترونية.
- إصدار فاتورة المبيعات: الحسابات، وترتيب البيانات (serialization)، والتوقيع (متراجع بـ `openssl cms -verify`)، والإرسال، وقفل الفاتورة بعد ما تتقبل.

الواتساب والمنظومة في الاختبارات **متمثّلين (simulated)**.

## قبل التشغيل مع عملاء حقيقيين

- [ ] تجربة قراءة الصور على فواتير حقيقية (مطبوعة ومكتوبة بخط اليد) وقياس الدقة.
- [ ] تجربة الربط مع المنظومة على preprod ببيانات حقيقية: السحب، وإصدار فاتورة مبيعات بتوكن حقيقي.
- [ ] تشغيل على سيرفر عليه HTTPS، وتفعيل `HTTPS_ONLY_COOKIES=true`، وعمل نسخة احتياطية يومية لفولدر `data/`.
- [x] بيانات دخول المنظومة (Client Secret) متخزنة متشفرة. خد نسخة من `ENCRYPTION_KEY` أو `data/.encryption_key` في مكان آمن.
- [ ] شروط استخدام واتفاقية سرية مع المحاسبين، لأن البيانات مالية.

> ⚠️ الأرقام دي أداة مساعدة، والمحاسب لازم يراجع قبل تقديم أي إقرار. الملخص بيحسب ضريبة القيمة المضافة (T1) بس، والقواعد الضريبية بتتغير، فراجعها مع مصلحة الضرائب.

## برنامج التوقيع (التوكن مع النسخة الأونلاين)

التوكن مابيترفعش على أي سيرفر: المفتاح جوه الشريحة ومابيطلعش منها. عشان كده فيه برنامج صغير لويندوز
(`signer_agent/`) بيتفتح على الكمبيوتر اللي التوكن متركب فيه:

1. صفحة الفاتورة في دفتر بتسأل البرنامج على `http://127.0.0.1:47321` عن الشهادات اللي على التوكن.
2. دفتر بيجهّز الفاتورة والبيانات اللي محتاجة توقيع، والبرنامج بيوقّعها بالتوكن (الرقم السري بيتكتب في شباك البرنامج بس).
3. دفتر بيركّب التوقيع (CAdES-BES) ويبعت الفاتورة للمنظومة.

- التحميل: `releases/latest/download/DaftarSigner.exe` — بيتبني لوحده على GitHub Actions (`.github/workflows/signer.yml`) مع كل تعديل في `signer_agent/`.
- بيتعرّف لوحده على تعريفات التوكنات المشهورة (ePass2003، eToken، IDPrime…). لو التعريف في مكان تاني اكتبه في
  `%APPDATA%\DaftarSigner\settings.json` كده: `{"pkcs11_library": "C:\\path\\driver.dll"}`.
- بيقبل يوقّع لدفتر الأونلاين ولأي نسخة على `localhost`. أي موقع تاني بيسأل المحاسب الأول.
- في الإعدادات لكل عميل: «مين بيوقّع» (توكن العميل أو توكن المكتب)، و«التوقيع بـ» = برنامج دفتر للتوقيع.
  النسخة الأونلاين (من غير وضع التجربة) بتستخدم البرنامج دايمًا.

## النشر أونلاين (Vercel + Supabase)

البرنامج بيشتغل بطريقتين بنفس الكود:
- **على جهاز المكتب (الأصل):** SQLite والملفات على الهارد، والقراءة المجانية (OCR) والتوقيع بالتوكن شغالين.
- **أونلاين:** Vercel للسيرفر و Supabase (PostgreSQL) للبيانات والملفات. الملفات بتتخزن في قاعدة البيانات، والقراية في الخلفية بتشتغل كل كام ثانية عن طريق `pg_cron` اللي بينادي `/internal/run-jobs`.

إعدادات Vercel (Environment Variables):

| المتغير | الوظيفة |
|---|---|
| `DATABASE_URL` | رابط PostgreSQL (Supabase pooler، port 6543). ممكن أكتر من رابط بينهم ` \| ` |
| `DB_SCHEMA` | `daftar` — الجداول في schema منفصلة مش ظاهرة في Supabase API |
| `SECRET_KEY`, `ENCRYPTION_KEY` | لازم يتحددوا (مفيش هارد دايم على Vercel) |
| `CRON_SECRET` | بيحمي `/internal/run-jobs` |
| `GEMINI_API_KEY` أو `ANTHROPIC_API_KEY` | القراءة بالذكاء الاصطناعي (مفيش OCR مجاني أونلاين) |

حدود النسخة الأونلاين: مفيش قراءة مجانية (OCR)، والتوقيع بالتوكن مش ممكن من السيرفر (التوكن على جهاز المحاسب)، فإصدار الفواتير الإلكترونية الحقيقي بيفضل من نسخة الجهاز.
